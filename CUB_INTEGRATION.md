## CUB Dataset Details

- **Source**: Caltech-UCSD Birds-200-2011 (Wah et al. 2011)
- **Raw location**: `data_cub-200-2011/CUB_200_2011/` (11,788 images, 200 classes)
- **Prepared location**: `data_cub_prepared/` (created by `prepare_cub.py`)

### Image counts per class after preparation:
- Train: 24–25 images (official train split minus 5 val holdout)
- Valid: 5 images (last 5 sorted-by-filename from official train)
- Test: 11–30 images (official test split)

### FSL Split (standard benchmark protocol):

| Split | Class IDs | Count | Role |
|-------|-----------|-------|------|
| Base | 1–100 | 100 | Episodic training + backbone training |
| ValFSL | 101–150 | 50 | Reserved (not used in this pipeline) |
| Novel | 151–200 | 50 | Few-shot evaluation (5-way episodes) |

**Reference**: Chen et al. ECCV 2019 "A Closer Look at Few-Shot Classification";
Tian et al. ECCV 2020 "Rethinking Few-Shot Image Classification"

## Key Differences: CUB vs Birds20

| Aspect | Birds20 | CUB-200-2011 |
|--------|---------|-------------|
| Total classes | 20 | 200 |
| Base classes | 15 or 10 | 100 |
| Novel classes | 5 or 10 | 50 |
| Train images/class | ~160 | 24–25 |
| Test images/class | 5 | 11–30 |
| Image style | Curated, bird-centred | Wild, varied backgrounds |
| Task difficulty | Easier (curated) | Harder (in-the-wild) |
| Eval n_way | 5 (= all novel) | 5 (randomly sampled from 50) |

### Impact on episodic training sampler

With only 24–25 training images per base class (vs ~160 for Birds20), the FewShotSampler
`need = k_shot + q_query = 1 + 15 = 16` is safely satisfied (24 ≥ 16). No config changes
needed; the existing `q_query=15` training setting works for CUB.

### Impact on evaluation

CUB test images per class range from 11–30. With `q_query=5` (the eval default), all
classes safely provide enough query images. With `k_shot=5`, the 24-image train split
also comfortably supports support sampling.

## Assumptions Made

1. **Standard FSL split**: Base=classes 1–100, ValFSL=101–150, Novel=151–200. This follows
   Chen et al. 2019 and is the most common protocol in the FSL literature for CUB.

2. **Val holdout**: Last 5 images (sorted by filename) from each class's official train
   split are reserved as validation. This is deterministic and reproducible.

3. **Class naming**: CUB folder names `NNN.ClassName` are stripped to `ClassName`
   (e.g. `001.Black_footed_Albatross` → `Black_footed_Albatross`).

4. **No data augmentation changes**: Same transforms as Birds20 (ImageNet normalisation,
   RandomResizedCrop for training, CenterCrop for eval).

5. **n_way=5 for evaluation**: Standard 5-way setup, randomly sampling 5 from 50 novel
   classes per episode (the scripts already handle n_way < n_novel).

---

## Remaining Limitations

1. **ValFSL classes (101–150) not used**: These 50 classes are saved in the split JSON
   but not wired into any training loop. A future extension could use them for episodic
   validation (instead of base-class val episodes) for more standard CUB benchmarking.

2. **No CUB-specific augmentation**: CUB in-the-wild images may benefit from stronger
   augmentation (e.g. larger crop scale, part-level attention). This is not implemented.

3. **Bounding boxes not used**: CUB provides per-image bounding boxes that could be used
   to crop images to the bird region before feature extraction. This pre-processing is
   not applied here; images are resized/cropped to 224×224 as-is.

4. **No Birds20 vs CUB comparison notebook**: A cross-dataset result comparison notebook
   is not yet implemented. Results are saved to separate `results/cub/` folders and can
   be compared manually or by extending the existing `result_comparison.ipynb`.

5. **TTA not configured for CUB**: ProtoNet+TTA is not added to the CUB configs but can
   be run by passing `--tta 8` to `train_evaluate/proto_net/evaluate.py` with a CUB config.
